# ESP32 RC Controller

Reworked Android controller for an ESP32-CAM 2WD RC car.

## What changed

- The transport is identified correctly as **Classic Bluetooth SPP**, not BLE.
- New `RcViewModel` owns Bluetooth/Wi-Fi control state and tuning.
- New Drive screen combines transport selection, hold-to-drive D-pad, speed, trim, light, and emergency stop.
- New Device screen handles paired-device connection, reconnect, Wi-Fi provisioning, IP/status, and protocol visibility.
- Existing camera controller and OpenCV auto-tracking features are retained.
- Runtime "C++ code" screen was removed; firmware now lives in `/firmware` where it belongs.
- Bluetooth writes are serialized; link errors and last-device reconnect state are exposed.
- Wi-Fi drive requests cancel stale drive calls to reduce command backlog.
- Android permission surface was reduced to what this SPP + LAN app actually needs.
- Firebase/Room/Secrets/AI Studio build baggage and dozens of patch scripts were removed.
- Firmware v3.0 fixes the old reboot behavior that alternated BT/Wi-Fi modes on every boot.

## App tabs

1. **Drive** — main controller and tuning
2. **Camera** — ESP32-CAM stream/capture/advanced controls
3. **Auto** — OpenCV tracking controller
4. **Device** — Bluetooth/Wi-Fi connection and provisioning

## Bluetooth pairing

Pair `ESP32_CAM_RC` in Android system Bluetooth settings first. The app uses the standard SPP UUID:

`00001101-0000-1000-8000-00805F9B34FB`

## Firmware

Open `firmware/ESP32_CAM_RC_Controller.ino` in Arduino IDE or PlatformIO. See `firmware/README.md` for the protocol.

## Build

Open the project in Android Studio, allow Gradle sync, then run the `app` configuration on Android 7.0+.

This export does not include a Gradle wrapper generated by AI Studio. If you want command-line builds, generate one once from a machine with Gradle/Android Studio available.
